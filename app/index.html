Phase 01 — Image Build
Dockerfile

The Dockerfile is the blueprint for our image. It starts from the official NGINX base image, copies our HTML files into the web root, exposes port 80, and starts the server. Every instruction creates a new layer in the image.

Dockerfile
# pull official nginx base image FROM nginx:latest # who built this LABEL maintainer="2523934@student.uwtsd.ac.uk" LABEL version="1.0" # clear default page, copy our HTML in RUN rm -rf /usr/share/nginx/html/* COPY app/ /usr/share/nginx/html/ # expose http port EXPOSE 80 # start nginx in foreground CMD ["nginx", "-g", "daemon off;"]
Phase 02 — Running Containers
Build & Run

After writing the Dockerfile we build the image using docker build which reads every instruction and creates a layered image. Then docker run starts a container from that image and maps port 8080 on the laptop to port 80 inside the container.

Phase 03 — Persistent Storage
Docker Volumes

By default when a container is deleted all data inside it is gone. Volumes fix this by storing data outside the container on the host machine. Essential for databases or anything that needs to survive container restarts.

PowerShell — volumes
docker volume create my-data-volume my-data-volume docker volume ls DRIVER    VOLUME NAME local     my-data-volume docker volume inspect my-data-volume Mountpoint: /var/lib/docker/volumes/my-data-volume/_data

Phase 04 — Container Network
Docker Networking

Docker networks let containers talk to each other using names as hostnames. Without a custom bridge network containers cannot reach each other by name — only by IP address which changes on every restart.

PowerShell — networks
